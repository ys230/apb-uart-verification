# 검토 가능한 v0.2 포트폴리오 결과까지의 로드맵

각 단계는 검증 증거를 기준으로 순서를 정했습니다. 해당 단계의 명령과 결과를 이 저장소에서 재현할 수 있을 때 완료로 간주합니다.

**현재 결과(2026-09-27):** v0.2의 0~5단계를 완료했습니다. 측정한 통과 기준과 남은 검증 범위는 [증거 보고서](../reports/evidence/v0.2/README.md)에 기록했습니다. GitHub Actions 워크플로는 저장소에 준비되어 있으며 GitHub에 게시하면 실행됩니다.

| 단계 | 수행할 작업 | 완료 기준과 결과물 |
|---|---|---|
| 0. 도구 준비 | Linux/WSL 환경을 기록하고 Verilator, C++ 컴파일러, GNU Make, Python을 준비합니다. | `verilator --version`, `make --version`, `g++ --version`으로 확인하고 버전을 시험 보고서에 기록합니다. |
| 1. 사양 확정 | APB 레지스터 맵, 대기·오류 응답, FIFO 경계 조건, UART 비트 타이밍을 확정합니다. | [`specification.md`](specification.md)와 [`verification-plan.md`](verification-plan.md)의 요구사항·검사 대응표를 완성합니다. |
| 2. 블록 구현 | 하나의 클록과 리셋을 사용하는 FIFO, UART TX/RX, APB 상위 모듈을 구현합니다. | `make lint` 통과, `rtl/` 아래의 소스 모듈을 확인합니다. |
| 3. 지정 시험 | 정상·비정상 APB 접근, UART 핀 타이밍, 수신 오류, FIFO 순서, 리셋을 검사합니다. | 자체 판정 테스트벤치 `tb/`, FIFO 단위 시험 통과, 대기 사이클 0/1/3에서 `apb`, `tx`, `rx` 시험 통과. |
| 4. 회귀 시험 | 고정 seed의 랜덤 전송과 결과 자동 수집을 추가합니다. | `make regress`에서 seed 20개 × APB 완료 전송 1,000건, FIFO 시험 1건, APB/TX/RX 지정 시험 9건이 모두 통과해야 합니다. 로그와 `summary.json`을 남깁니다. |
| 5. 포트폴리오 증거 | 커버리지 미달 항목을 검토하고 알려진 결함 하나를 주입해 검출을 확인하며 실제 버그 수정 사례와 결과를 기록합니다. | `make mutation`, README 결과표, 대표 파형, 버그 기록, 도구·버전·소스 해시, 시험한 분주값·프레임 수·검증 범위를 남깁니다. |

1~4단계는 설계와 검증 작업이며, 5단계는 다른 사람이 결과를 확인하고 재현할 수 있게 만드는 단계입니다. 각 명령의 실행 순서, 성공 표시, 로그 위치는 [README의 실행 안내](../README.md#처음-실행하기)를 참고하세요. UVM은 이 기준을 통과한 뒤 선택적으로 확장할 수 있습니다. RTL 설계 직무를 목표로 한다면 합성·타이밍 보고서와 FIFO 및 클록 인에이블 설계 선택의 근거를 추가하세요.

최초 제안서에는 당시 사용한 Windows 경로가 기록되어 있습니다. 이 로드맵의 프로젝트 명령은 복제한 저장소의 최상위 디렉터리에서 실행합니다. 실제 도구 버전은 설치 후 확인해 기록하며 제안서의 버전을 그대로 가정하지 않습니다.
