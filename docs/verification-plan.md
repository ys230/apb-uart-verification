# v0.2 검증 및 증거 계획

테스트벤치는 버스 마스터로서 APB를 구동하고, 외부 핀에서 TX를 디코딩하며, 독립적인 직렬 소스로 RX를 구동한다. 예상 데이터는 DUT 외부에 보관한다. 데이터 불일치, 프로토콜 타임아웃 또는 assertion 실패가 발생하면 프로세스가 반드시 0이 아닌 종료 코드를 반환해야 한다.

| ID | 요구사항 | 입력 및 조건 | 독립적인 검사 | 증거 |
|---|---|---|---|---|
| APB-01 | 리셋 값과 APB 설정/접근 타이밍 | 리셋, 정상 읽기/쓰기, 대기 0/1/3 | 읽어낸 값과 관측한 `PREADY` 타이밍 | APB 지정 테스트 로그 |
| APB-02 | 완료된 전송당 부수 효과 한 번 | 접근 단계 유지 및 연속 설정/접근 전송 | TX 프레임, RX FIFO 순서, APB 카운터 | APB/TX/RX 지정 테스트 로그 |
| APB-03 | 오류 시 상태 유지 | 유효하지 않은 주소, 비정렬 주소, RO/WO 위반, 가득 참/비어 있음 상태의 접근 | `PSLVERR`, 오류 읽기 데이터 0, 읽어낸 값과 순서 유지 | APB/RX 지정 테스트 로그 |
| APB-04 | 프로토콜 및 오류 상태 assertion | 정상/오류 전송 및 ACCESS 유지 | SVA로 ready/error 타이밍, 완료 한 번, 오류 후 제어 상태 유지 검사 | assertion을 활성화한 테스트 로그 |
| FIFO-01 | FIFO의 바이트 순서 및 경계 정책 유지 | 채우기, 비우기, 포인터 순환, 동시 입력/출력 | 기대값 큐와 외부에서 읽거나 디코딩한 바이트 | TX/RX 지정 테스트 로그 |
| TX-01 | 8N1, 최하위 비트 우선, 설정한 비트 길이 | 00/FF/55/AA 및 랜덤 바이트 | 독립적인 핀 디코더와 프레임 비트 길이 검사 | TX 지정 테스트 및 랜덤 테스트 로그 |
| RX-01 | 유효한 8N1 수신 | 독립 소스가 분주 값 4, 5, 16, 32에서 알려진 바이트와 랜덤 바이트를 전송하고, DUT 분주 값이 32일 때 비트 길이 31/33으로 전송 | 소스 기대값 큐와 RXDATA 읽기 결과 비교 | RX 지정 테스트 및 랜덤 테스트 로그 |
| RX-02 | 거짓 시작, 프레이밍 오류, 오버플로, RX 비활성화 | 잘못된 입력 프레임 및 가득 찬 FIFO | 데이터 폐기와 STATUS의 sticky 비트 | RX 지정 테스트 로그 |
| SYS-01 | 리셋 시 진행 중인 작업 중단 | APB 대기 및 UART 프레임 도중 리셋 | 리셋 후 읽기 결과, 빈 FIFO, 유휴 TX | APB/TX/RX 지정 테스트 로그 |

## v0.2 완료 기준

1. `make lint`에서 억제되지 않은 경고나 오류가 없어야 한다.
2. FIFO 단위 테스트가 통과하고, `WAIT_CYCLES=0`, `1`, `3` 각각에서 APB, TX, RX 지정 테스트가 통과해야 한다.
3. 고정 seed 20개가 각각 완료된 APB 전송 최소 1,000건으로 통과해야 한다. 세 대기 설정은 seed에 걸쳐 순환 적용한다. 보고서에는 TX/RX 프레임 수, 도구 버전, 소스 해시, seed, 명령, 종료 상태, 로그 경로도 기록한다.
4. 위의 필수 기능 시나리오를 실제로 관측해야 한다. README에 TX/RX 프레임 수, 시험한 baud 분주 값, 실행되지 않은 시나리오, 도구 또는 코드 커버리지의 한계를 기록한다. 횟수만으로 정확성이 입증되는 것은 아니며, scoreboard와 assertion도 통과해야 한다.
5. 의도적으로 삽입한 RTL 결함이 자동 검사에서 적어도 하나 검출되고, 일반 개발 과정에서 발견한 결함과 구분하여 문서화되어야 한다. 의도적으로 거짓인 SVA가 설정된 시뮬레이터에서 실패하는지도 확인한다. 실제 디버깅 사례 하나의 재현 절차, 원인, 수정 내용을 기록한다.
6. 새 환경에서 README의 절차에 따라 수동 수정 없이 `make lint`, `make test`, `make regress`를 실행할 수 있어야 한다.

회귀 테스트 실행기는 전체 로그와 JSON/Markdown 요약을 `reports/runs/latest/` 아래에 기록한다. 검증된 실행 후에는 간추린 결과와 대표 파형을 `reports/evidence/`에 복사할 수 있다. 생성된 빌드 파일과 원본 파형은 Git에서 제외한다.
